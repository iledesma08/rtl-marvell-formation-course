03 — Formato de datos: ¿cómo se lee un número en punto fijo?

Todo el módulo trabaja en punto fijo (fixed-point). Un número se representa con un bit de signo y un número fijo de bits fraccionarios. La notación S(A,B) significa:

S  ->  signed (con signo, en complemento a 2)
A  ->  ancho total en bits (incluye signo y parte entera)
B  ->  cantidad de bits fraccionarios

S(16,15) — las entradas x, y y la salida R

  • Ancho total: 16 bits → [15:0]
  • Parte fraccionaria: 15 bits → el valor real es entero / 2^15
  • Parte entera: 1 bit (2^15 / 2^15 = 1), así que el rango es [-1, 1).

Cómo interpretar

0x4000  = 16384 / 32768 = 0.5
0x7FFF  = 32767 / 32768 ≈ 0.99997   (casi 1)
0x8000  = -32768 / 32768 = -1.0
0xFFFF  = -1 / 32768 ≈ -0.00003     (casi -0)
0x0001  = 1 / 32768 ≈ 0.00003       (el valor positivo más chico) = 1 ULP

ULP = unidad en el último lugar, el paso más chico que se puede representar: 2^-15.

Limitación importante

Con x, y ∈ [-1, 1), la magnitud R = sqrt(x² + y²) puede llegar hasta sqrt(2) ≈ 1.414, que no entra en S(16,15) (cuyo máximo es 1.0).

Por eso el código satura la salida a 0x7FFF (R = 1.0) cuando el resultado excede el rango, y los vectores de test usan R ∈ [0.2, 0.95] para quedar dentro del rango.

if (X_next > 32767)  R_next = 32767;   -> satura a 1.0

S(16,14) — la salida phi y la tabla atan(2^-i)

  • Ancho total: 16 bits → [15:0]
  • Parte fraccionaria: 14 bits → el valor real es entero / 2^14
  • Parte entera: 2 bits → rango [-2, 2).

El problema: phi va de -π a +π ≈ [-3.1416, 3.1416], que tampoco entra en [-2, 2).

Solución: expresar phi en unidades de π

En vez de guardar el ángulo en radianes, se guarda ángulo / π:

phi (unidades de π)  =  valor / 2^14

valor = 1.0  ->  π radianes  (una media vuelta)
valor = 0.5  ->  π/2
valor = -1.0 ->  -π

Así el círculo completo (-π, π] mapea a (-1, 1], que entra holgado en S(16,14) (rango [-2, 2)). Esta es la decisión clave que toma el README.

En el código, la constante PI_1 = 16384 es exactamente π en unidades de π (1.0 * 2^14 = 16384). Por eso sumar PI_1 al ángulo equivale a sumar π, y la corrección de cuadrante pasa a ser sumar/restar 1.0 exacto.

S(18,15) — los registros internos X e Y

  • Ancho total: 18 bits → [17:0]
  • Parte fraccionaria: 15 bits (igual que la entrada) → el valor real es entero / 2^15
  • Parte entera: 3 bits → rango [-4, 4).

¿Por qué 18 bits si la entrada es de 16?

Son bits de guarda (guard bits): dan margen para que las sumas/restas de las iteraciones no desborden. Recuerda que X·K ya puede ser grande, y que las micro-rotaciones suman valores que pueden crecer un poco. Con 3 bits de parte entera hay espacio antes de saturar.

Además, X_e Y se usan con signo y pueden tomar valores negativos transitoriamente durante el proceso, así que necesitan más que 16 bits.

Resumen de formatos

Señal Formato Rango real Interpretación
x, y (in) S(16,15) [-1, 1) coordenadas del vector
R (out) S(16,15) [0, 1] (sat) magnitud
phi (out) S(16,14) [-1, 1] (π units) ángulo / π
X, Y (int) S(18,15) [-4, 4) datapath con guard bits
z / Z (int) S(16,14) [-2, 2) acumulador de ángulo (π units)

Regla para leer los archivos: cada 16'sd4096 u 18'sd19898 se interpreta como un entero que hay que dividir por 2^fraccionaria.

En atan_lut.vh el comentario // atan(2^-0)/pi * 2^14 y el valor 4096 confirman: atan(2^-0)/π * 2^14 = 0.25 * 16384 = 4096.
