05 — Decisiones de diseño que importan

Este documento explica los "por qué" del diseño: las decisiones que separan una implementación correcta de una buena implementación. Cada una tiene su equivocación típica.

1. Arquitectura folded (reutilizar el datapath)

El módulo es folded: hay un solo bloque de rotación, y se reutiliza 16 veces (una por iteración), en 16 ciclos de reloj.

Alternativa: unfolded / pipeline (lo que viste en el ejercicio 2), donde hay 16 bloques encadenados, cada uno en su propio ciclo. Eso da más throughput pero mucha más área.

Trade-off: folded = mínima área, latencia fija de 16 ciclos, poco throughput (se procesa un vector a la vez). Para este ejercicio el folding es lo pedido y lo más simple.

2. Pre-escalado por K al inicio (no al final)

La ganancia total del CORDIC es K = ∏cos(atan(2^-i)) ≈ 0.60725. Hay dos formas de compensarla:

  • Al final: dividir el resultado por K. Dividir es caro.
  • Al inicio: multiplícá la entrada por K. Como K es constante, x·K se sintetiza como sumas y desplazamientos (shifters y sumadores), no como multiplicador real. Es un truco clásico de "multiply by constant".

Por qué acá: como se pre-escala, al final X = R directo, sin división. El precio es que hay que cuidar el ancho (el producto x·K necesita 32 bits).

Ojo con el ancho

logic signed [31:0] x_prod, y_prod;   // x*K, y*K: 32767*19898 ~ 2^30, no cabe en 16

32767 * 19898 ≈ 6.5e8 es más grande que 2^15. Hay que acumular el producto en 32 bits (o más), y luego redondear de vuelta a 16 con >>> 15.

3. Pre-rotación de 180° si x < 0

El rango de convergencia del CORDIC es ≈ ±0.555π (más que ±90°, menos que ±π). Un vector con x < 0 tiene ángulo fuera de ese rango.

Truco (sugerido por el enunciado): si x < 0, usá (-x, -y). Así el ángulo queda en [-π/2, π/2], dentro del rango. La magnitud no cambia.

El truco para mantener el resultado: guardar los signos originales (x_neg, y_neg) y, al final, corregir el ángulo reconstruyendo el cuadrante. Ver sección 4.

4. Corrección de cuadrante sobre z

Como la pre-rotación de 180° altera el ángulo, hay que "deshacerla" (sumar o restar π) según el cuadrante real del vector:

x >= 0           ->  φ = z        (cuadrantes I y IV)
x < 0, y >= 0    ->  φ = z + π    (cuadrante II)
x < 0, y <  0    ->  φ = z − π    (cuadrante III)

En el código esto es un if/else if/else sobre x_neg/y_neg.

Bonus: expresar todo en unidades de π

Al hacer esto en unidades de π (formatos S(16,14)), sumar/restar π se vuelve sumar/restar 1.0 exacto (PI_1 = 16384), en vez de 3.14159.... Cero error de redondeo en la corrección.

5. Redondeo a nearest en los desplazamientos

Las micro-rotaciones hacen X·2^-i e Y·2^-i. Si se trunca el desplazamiento (descartar los bits de abajo), se pierde precisión: el error del CORDIC sube 1–2 ULP.

Solución: round_shift suma 2^(sh-1) antes de desplazar, que es redondear al valor más cercano:

r = r + (18'sd1 << (sh - 1));    // redondea
round_shift = r >>> sh;           // desplaza

Este es un detalle pequeño que marca la diferencia entre 4 ULP y 6 ULP de error. El README destaca que es "lo que mantiene el error del CORDIC en ~1 ULP típico".

6. Bits de guarda (guard bits): S(18,15)

El datapath interno usa X, Y ∈ S(18,15) en vez de S(16,15):

  • 3 bits de parte entera (rango [-4, 4)) dan espacio para las sumas/restas y el crecimiento transitorio del proceso.
  • Sin ellos, las sumas intermedias desbordarían 16 bits y darían resultados erróneos.

Esos bits "extra" son baratos (2 bits) y se descartan al final (se truncan a 16 para R).

7. FSM implícita: el contador i + busy/done

No hay una FSM explícita de estados como en el ejercicio 1. El control es:

  • i (contador 0..15) = índice de iteración.
  • busy = está resolviendo.
  • done = pulso de 1 ciclo, resultado listo.

Esto es una máquina de estados implícita: el "estado" está codificado en busy e i. Latencia fija de 16 ciclos, done registrado de un pulso.

8. Sin multiplicador real, sin ROM grande

El módulo no instancia un multiplicador ni una ROM grande. Todo el "cómputo" es:

  • Sumas / restas (los + / - de las rotaciones).
  • Desplazamientos aritméticos (>>>, y los 2^-i).
  • Una tabla de 16 constantes atan(2^-i) absorbida como lógica combinacional.

Por eso Yosys reporta ROM = 0 y # celdas lógicas = 17293. Esa es la ventaja central que el ejercicios quiere destacar: mismo resultado que la referencia directa, con cero memoria y sin multiplicador.
