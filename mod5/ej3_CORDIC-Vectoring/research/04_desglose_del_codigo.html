04 — Desglose línea a línea de cordic_vect.sv

Este documento recorre el módulo de arriba a abajo, en el mismo orden en que está escrito el archivo. Usamos los números de línea del archivo original.

Cabecera y comentario (líneas 1–36)

El bloque de comentario inicial resume las dos salidas y los formatos:

R   = sqrt(x^2 + y^2)     <- S(16,15) saturado
phi = atan(y/x)           <- S(16,14) en unidades de π

Arquitectura: folded = el mismo datapath se reutiliza en N_ITER = 16 ciclos (una iteración por ciclo). Ver 05 para qué significa "folded".

Interfaz del módulo (líneas 37–49)

module cordic_vect (
  input  logic                clk,
  input  logic                rst_n,
  input  logic                start,        // pulso que inicia un cálculo
  input  logic signed [15:0]  x,            // S(16,15)
  input  logic signed [15:0]  y,            // S(16,15)
  output logic signed [15:0]  R,            // S(16,15) saturado
  output logic signed [15:0]  phi,          // S(16,14), unidades de π
  output logic                done,         // pulso de 1 ciclo: resultado listo
  output logic                busy           // está trabajando
);
  • start: dispara un cálculo (un pulso).
  • done: pulso de 1 ciclo cuando el resultado está listo.
  • busy: alto mientras el datapath está resolviendo iteraciones.
  • R, phi: los resultados, válidos el mismo ciclo en que se ve done.

Constantes (líneas 51–53)

localparam int N_ITER       = 16;
localparam signed [15:0] K_Q = 16'sd19898;   // 0.6072529... en S(16,15)
localparam signed [15:0] PI_1 = 16'sd16384;  // 1.0 en unidades de π
  • N_ITER = 16: 16 iteraciones = 16 ciclos de latencia.
  • K_Q = 19898: 0.6072529 * 2^15 ≈ 19898. La constante de escala del CORDIC.
  • PI_1 = 16384: π en unidades de π (ver 03).

Registros del datapath (líneas 55–62)

logic signed [17:0] X, Y;        // S(18,15) de 18 bits (guard bits)
logic signed [17:0] X_next, Y_next;
logic signed [15:0] Z;           // S(16,14), unidades de π
logic signed [15:0] Z_next;
logic        [3:0]  i, i_next;   // índice de iteración (0..15)
logic               x_neg, y_neg; // signos ORIGINALES para el cuadrante
logic signed [15:0] atan_val;

Estos son los registros que se actualizan en cada iteración. X_next, Y_next, Z_next, i_next son las versiones combinacionales del próximo valor (se calculan en always_comb y se cargan en el always_ff).

Pre-escalado por K (líneas 64–87)

Este bloque prepara el vector (x, y) de entrada:

assign x17 = x;                       // extiende x a 17 bits
assign y17 = y;
assign x_rot = x17[16] ? -x17 : x17;  // pre-rotación 180° si x < 0
assign y_rot = x17[16] ? -y17 : y17;

assign x_prod = $signed(x_rot) * $signed(K_Q);  // x·K en 32 bits
assign y_prod = $signed(y_rot) * $signed(K_Q);  // y·K en 32 bits
assign x_ps = (x_prod + 32'sd16384) >>> 15;     // redondea y vuelve a 16 bits
assign y_ps = (y_prod + 32'sd16384) >>> 15;

// Extiende a S(18,15) de 18 bits
assign xps18 = x_ps;
assign yps18 = y_ps;

Desglosemos:

  1. Extensión a 17 bits (x17, y17): necesaria porque x es S(16,15) y vamos a negarlo en la pre-rotación. Si x = -32768 (el mínimo), -x desbordaría 16 bits, así que se toma en 17.
  2. Pre-rotación de 180° (x_rot, y_rot): si x < 0 (bit 16 = signo), se usa (-x, -y). Esto lleva el ángulo al rango de convergencia.
assign x_rot = x17[16] ? -x17 : x17;
  1. El producto por K (x_prod, y_prod): signed 17 × signed 16 da hasta 33 bits; se declara de 32 ([31:0]). El comentario aclara por qué no puede ser 16: 32767 * 19898 ≈ 2^30, no cabe en 16 bits.
  2. Redondeo a nearest (>>> 15): después de sumar 16384 (= 2^15 / 2), el >>> es un desplazamiento aritmético (divide por 2^15). Sumar la mitad del 2^15 antes de desplazar = redondear al valor más cercano en vez de truncar.
  3. Extensión a 18 bits (xps18, yps18): con S(18,15) para el registro.

Importante: x_neg y y_neg se guardan después, en always_ff, usando los signos originales x[15], y[15] — no los pre-rotados. Por eso la corrección de cuadrante al final sabe el cuadrante real.

Función de redondeo (líneas 90–101)

function automatic logic signed [17:0] round_shift(
    input logic signed [17:0] v, input logic [3:0] sh);
  logic signed [17:0] r;
  begin
    r = v;
    if (sh != 0)
      r = r + (18'sd1 << (sh - 1));   // suma media LSB para redondear
    round_shift = r >>> sh;            // desplaza (divide por 2^sh)
  end
endfunction

round_shift(v, sh) devuelve round(v·2^-sh). Es la operación clave de las micro-rotaciones: desplazar Y e X por i, pero con redondeo a nearest.

  • r + (1 << (sh-1)): sumar 2^(sh-1) redondea.
  • r >>> sh: desplazamiento aritmético (divide por 2^sh, conservando signo).

Sin este redondeo (truncando a secas), el error del CORDIC subiría 1–2 ULP extra. Ver 05.

Lógica combinacional de la iteración (líneas 103–160)

El always_comb (línea 111)

Este bloque calcula los *_next. Recuerda que arranca con defaults para evitar latches:

X_next = X;   Y_next = Y;   Z_next = Z;   i_next = i;
d      = -16'sd1;
rx = 0;       ry = 0;
R_next = R;   phi_next = phi;

El start (líneas 123–130)

if (start) begin
  X_next = xps18;     // precarga el vector pre-escalado
  Y_next = yps18;
  Z_next = 16'sd0;    // ángulo arranca en 0
  i_next = 4'd0;
end

En el ciclo en que start está activo, solo se precarga el vector. La iteración 0 se resuelve en el siguiente ciclo, cuando busy = 1 e i = 0.

El cuerpo de la iteración (líneas 130–143)

end else begin
  // Decision del vectoring: rotar hasta llevar Y a cero.
  d = (Y >= 0) ? -16'sd1 : 16'sd1;

  // Productos rotacionales con redondeo.
  rx = round_shift(Y, i);
  ry = round_shift(X, i);

  X_next = (d == 1) ? X - rx : X + rx;
  Y_next = (d == 1) ? Y + ry : Y - ry;
  Z_next = (d == 1) ? Z - atan_val : Z + atan_val;

  i_next = (i == N_ITER - 1) ? 4'd0 : i + 1;
end

Comparalo con la fórmula teórica de 02:

d = signo:  (y >= 0) ? -1 : +1
X' = X − d·Y·2^-i
Y' = Y + d·X·2^-i
Z' = Z − d·atan(2^-i)

El código lo implementa exactamente:

  • d = (Y >= 0) ? -1 : +1: el autómata del always_comb. Si Y ≥ 0 hay que bajarlo (girar horario, d = -1); si Y < 0, subirlo (d = +1).
  • rx = round_shift(Y, i) es Y·2^-i con redondeo.
  • ry = round_shift(X, i) es X·2^-i con redondeo.
  • Alternativamente en X_next según d. Cuando d = +1: X - rx e Y + ry (y Z - atan). Cuando d = -1: X + rx, Y - ry, Z + atan. (Recordá que d juega "al revés": la fórmula usa -d. d=+1 → X−rx, Y+ry, Z−atan; d=−1 → X+rx, Y−ry, Z+atan. Coincide.)
  • i_next: cuenta ciclos; al llegar a 15 (última), vuelve a 0.

Salida R con saturación (líneas 145–151)

if (X_next > 18'sd32767)
  R_next = 16'sd32767;       // satura a 1.0
else if (X_next < 18'sd0)
  R_next = 16'sd0;           // no negativo
else
  R_next = X_next;           // trunca a 16 bits

Después de 16 iteraciones, X es la magnitud R. Si excede 0x7FFF (que es 1.0 en S(16,15)) se satura. Si es negativo (no debería, pero por seguridad) da 0. Si no, se truncan los 16 bits bajos (los altos ya son 0 porque X < 2^15).

Salida phi con corrección de cuadrante (líneas 153–159)

if (!x_neg)
  phi_next = Z_next;            // cuadrante I o IV: φ = z
else if (!y_neg)
  phi_next = Z_next + PI_1;     // cuadrante II: φ = z + π
else
  phi_next = Z_next - PI_1;     // cuadrante III: φ = z − π

Como la pre-rotación de 180° cambió el signo, hay que deshacerla según el cuadrante real (guardado en x_neg/y_neg):

x >= 0           ->  φ = z        (cuadrantes I y IV)
x < 0, y >= 0    ->  φ = z + π    (cuadrante II)
x < 0, y <  0    ->  φ = z − π    (cuadrante III)

PI_1 es π en unidades de π (código: 16'sd16384).

Cuidado: acá el if usa x_neg/y_neg que ya están registrados en always_ff, no los valores combinacionales. Esto es correcto porque son los signos originales de entrada.

Resparto secuencial (líneas 162–199)

El always_ff (línea 165)

Este bloque carga los registros en cada flanco.

Reset (líneas 166–176): pone todo a 0, busy = 0, done = 0.

Operación normal (líneas 177–198):

done <= 1'b0;                    // done es un pulso de 1 ciclo
if (start) begin
  X     <= xps18;                // precarga
  Y     <= yps18;
  Z     <= 16'sd0;
  i     <= 4'd0;
  busy  <= 1'b1;                 // arranca a resolver
  x_neg <= x[15];                // guarda signos ORIGINALES
  y_neg <= y[15];
end else if (busy) begin
  X   <= X_next;
  Y   <= Y_next;
  Z   <= Z_next;
  i   <= i_next;
  R   <= R_next;
  phi <= phi_next;
  if (i == N_ITER - 1)
    done <= 1'b1;                // R/phi válidos en este ciclo
  busy <= (i != N_ITER - 1);     // sigue hasta la última iteración
end

Puntos clave:

  • done <= 1'b0 al inicio de cada ciclo: garantiza que done es un pulso de 1 ciclo (a menos que en este ciclo se apague en alto).
  • En el ciclo de start, se capturan los signos originales en x_neg/y_neg y se pone busy.
  • En cada ciclo de busy, se cargan los *_next calculados por el always_comb.
  • Cuando i == N_ITER - 1 (la iteración 15, la última), se marca done y busy se apaga. En ese mismo ciclo, R y phi ya tienen el valor final.

Latencia

Desde start hasta done hay N_ITER = 16 ciclos: - Ciclo de start: precarga (iteración i=0 todavía no corre). - Ciclos 1..16: iteraciones i = 0..15. Al final del ciclo 16, done y los resultados válidos.

La ROM de atan (líneas 201–207)

rom_atan u_rom (
  .index(i),
  .value(atan_val)
);

Instancia de rom_atan.sv, que es una ROM de 16 entradas (generada por gen_roms.py). i es el índice de iteración; atan_val es el atan(2^-i) en unidades de π, S(16,14). Se usa en la actualización de Z.

Cómo es rom_atan.sv

module rom_atan (
  input  logic [3:0]         index,       // 0..15
  output logic signed [15:0] value
);
  always_comb begin
    `include "atan_lut.vh"    // la tabla generada
  end
endmodule

El include inyecta un case(index) (ver atan_lut.vh):

index 0    ->  4096   = atan(1)/π · 2^14 = 0.25
index 1    ->  2418   = atan(0.5)/π · 2^14
index 2    ->  1278   ...

Como es always_comb con un case completo, el sintetizador la convierte en lógica combinacional, no en una ROM real. Por eso el CORDIC reporta ROM = 0 bits en Yosys.
