3. Lectura detallada de nr_div.sv

Interfaz

Señal Dirección Función
clk entrada reloj; toda captura ocurre en posedge
rst_n entrada reset asíncrono activo en bajo
start entrada solicita una operación; a debe estar estable
a[15:0] entrada divisor normalizado en U(16,16)
y[15:0] salida recíproco en U(16,15)
done salida indica que el resultado terminó
busy salida el bloque no está disponible para otra operación

start no es una cola: si llega mientras busy está alto, la FSM lo ignora. El uso normal es un pulso de un ciclo con a válido.

Registros y señales internas

Las declaraciones están en las líneas 53-67:

Señal Ancho Papel
state 2 estado de la FSM
a_reg 16 copia de a capturada al iniciar
y_reg 16 semilla, iteración actual o resultado
p1_reg 32 producto a_reg * y_reg entre MUL1 y MUL2
iter ITER_W número de iteración actual
y0 16 lectura combinacional de la LUT
mul_x 16 operando izquierdo del multiplicador compartido
mul_out 32 producto combinacional
p1_hi 16 p1 redondeado y reescalado
t 16 factor 2 - a*y
y_new 16 siguiente aproximación, redondeada y saturada

La LUT se lee antes de capturar

assign y0 = lut_y0((a >> 12) & 3'h7);

El índice (a >> 12) & 7 elige uno de los 8 bins del rango normalizado: con a en U(16,16) vale de 8 a 15 y el & 7 lo lleva a [0, 7]. La explicación paso a paso (formato, por qué el shift por 12 y la máscara) está en Punto fijo y LUT · cómo se construye la LUT.

y0 depende de la entrada externa a, no de a_reg. En el estado IDLE, al flanco que acepta start, el bloque hace simultáneamente:

a_reg <= a;
y_reg <= y0;

Por ello el testbench aplica a y start en negedge, dejando medio período de setup antes del posedge. Si un entorno real cambia la entrada demasiado cerca del flanco, puede capturarse una semilla equivocada.

El multiplicador folded

El diseño tiene un único multiplicador físico/combinacional:

assign mul_x   = (state == MUL1) ? a_reg : t;
assign mul_out = mul_x * y_reg;

El mismo recurso hace trabajos diferentes según el estado:

  • En MUL1: mul_out = a_reg * y_reg.
  • En MUL2: mul_out = t * y_reg.

Esto se llama datapath folded: se ahorra área reutilizando el operador, a cambio de usar dos ciclos por iteración. Una versión desenrollada o pipeline podría colocar más multiplicadores y aceptar más operaciones por unidad de tiempo.

Cálculo combinacional de una iteración

Paso 1: producto de corrección

En MUL1, el producto sale del multiplicador y se registra:

p1_reg <= mul_out;

Paso 2: factor t

p1_wide = {1'b0, p1_reg} + 33'h8000;
p1_hi   = p1_wide[31:16];
t_ext   = 17'h10000 - {1'b0, p1_hi};
t       = t_ext[15:0];

El bit extra evita perder información durante la resta. Para entradas válidas, el valor que se registra como t cabe en 16 bits.

Paso 3: nueva aproximación

mul_rnd = {1'b0, mul_out} + 33'h4000;
y_new   = (mul_rnd[32:15] >= 18'h10000)
          ? 16'hFFFF
          : mul_rnd[31:15];

El primer camino implementa round((t*y) / 2^15). El segundo evita wrap-around si el resultado necesita el código 0x10000 o más.

La FSM

Los estados son constantes de dos bits:

IDLE = 0, MUL1 = 1, MUL2 = 2, DONE = 3

En el always_ff:

Estado actual Condición Acción en el flanco Estado siguiente
IDLE start=0 espera IDLE
IDLE start=1 captura a, carga y0, pone iter=0 MUL1
MUL1 siempre registra p1 = a*y MUL2
MUL2 última iteración registra y_new DONE
MUL2 no última registra y_new, incrementa iter MUL1
DONE start=0 libera el bloque IDLE
DONE start=1 mantiene el resultado DONE

busy y done no son registros independientes:

assign busy = (state != IDLE);
assign done = (state == DONE);

Así, done dura un ciclo si start fue un pulso. Si el entorno deja start alto, la FSM permanece en DONE y done también permanece alto; el protocolo esperado exige retirar start.

Seguimiento temporal para N_ITER = 2

Contando el flanco que acepta start como ciclo 0:

Flanco Estado anterior Acción Estado después
0 IDLE captura a, carga y0 MUL1
1 MUL1 guarda p1 de la iteración 0 MUL2
2 MUL2 guarda y1, iter=1 MUL1
3 MUL1 guarda p1 de la iteración 1 MUL2
4 MUL2 guarda y2 DONE

El resultado queda registrado al flanco 4 y done queda alto durante el ciclo posterior a ese flanco. El testbench cuenta el aviso en 5 ciclos porque espera en posedge antes de observar el valor actualizado por NBA de SystemVerilog. Por eso el contrato documentado y medido es 2*N_ITER + 1 desde el start del testbench.

Qué ocurre después de DONE

y está conectado permanentemente a y_reg, así que conserva el resultado. Al volver a IDLE, no se borra automáticamente. La señal que dice si ese valor es el resultado de la operación actual es done, no un cambio de y.

Investigación guiada del ejercicio Newton-Raphson. Si algo no queda claro, pregunta por la señal, el ciclo o la escala exacta.
