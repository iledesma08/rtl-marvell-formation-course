Fuentes primarias: divisor por Newton-Raphson

Nota breve para ej4_NewtonRaphson. Las afirmaciones matemáticas y de implementación se separan: las primeras describen el algoritmo real; las segundas documentan decisiones necesarias al llevarlo a aritmética de punto fijo.

Newton-Raphson y recíproco

  • NIST define una raíz como una solución de f(z) = 0 y una raíz simple como aquella para la que f(zeta) = 0 y f'(zeta) != 0. NIST DLMF, 3.8(i)
  • La regla de Newton es z[n+1] = z[n] - f(z[n])/f'(z[n]). Para el recíproco de a != 0, se aplica a f(y) = 1/y - a; al simplificar f'(y) = -1/y^2, resulta y[n+1] = y[n](2 - a*y[n]). La primera fórmula es la regla documentada por NIST; la segunda es su derivación algebraica para esta función. NIST DLMF, 3.8(ii), ecuación 3.8.4
  • Si y* = 1/a y e[n] = y[n] - y*, la iteración exacta satisface e[n+1] = -a*e[n]^2. Por tanto, el error se eleva al cuadrado mientras se permanezca en la región de convergencia. Es la especialización algebraica de la iteración anterior; NIST establece que Newton converge local y cuadráticamente para una raíz simple. NIST DLMF, 3.8(i)-(ii)
  • NIST define convergencia de orden p mediante |z[n+1]-zeta| < A|z[n]-zeta|^p para n suficientemente grande; p = 2 se llama convergencia cuadrática. Esto no garantiza convergencia desde cualquier semilla: la afirmación de Newton es local. NIST DLMF, ecuación 3.8.3 y 3.8(ii)

Representación fixed-point

  • En una representación fixed-point, una palabra separa bits enteros y fraccionarios alrededor del punto binario. La documentación de AMD expresa el formato como ap_fixed<W,I>: W es el ancho total e I el número de bits a la izquierda del punto, incluido el signo en formatos con signo. La misma idea, sin bit de signo, permite interpretar U(16,16) como X/2^16 y U(16,15) como X/2^15. AMD Vitis HLS UG1399, tipos fixed-point
  • Al multiplicar dos enteros codificados con F1 y F2 bits fraccionarios, el producto tiene F1+F2 bits fraccionarios; para volver al formato destino se desplaza y cuantiza. La documentación oficial de CMSIS-DSP modela explícitamente tipos fixed-point con M bits de mantisa y F bits fraccionarios, y ofrece una multiplicación que conserva el formato ampliado. Arm CMSIS-DSP, fixed point datatypes
  • Más bits fraccionarios aumentan la resolución pero reducen el rango disponible; elegir U(16,15) para 1/a con a normalizado en [0.5,1) permite representar (1,2), mientras que el valor ideal 2 requiere el código 2*2^15 = 0x10000, que excede 16 bits. El límite representable es 0xffff, de modo que una salida de 16 bits debe saturarse en ese caso. Es una consecuencia numérica del formato y de la definición de ancho/punto binario de AMD. AMD Vitis HLS UG1399

Redondeo y saturación

  • Al reducir la precisión de un producto, truncar descarta bits; redondear a nearest usa la información del bit siguiente. Microchip documenta tres modos para operaciones fixed-point: truncación, nearest convencional y nearest convergente (empates hacia par). Para esta implementación unsigned, floor((P + 2^(S-1))/2^S) es una elección concreta de nearest, con empates hacia arriba. Microchip MPLAB XC-DSC, sección 10.3 Rounding
  • Saturar significa limitar el resultado al máximo o mínimo representable en vez de dejar que el overflow envuelva la palabra. AMD distingue modos de cuantización y overflow, incluido AP_SAT (saturación) frente a AP_WRAP (wrap-around); CMSIS-DSP también expone una operación para saturar un tipo más ancho al tipo destino. AMD Vitis HLS UG1399; Arm CMSIS-DSP, saturate
  • En consecuencia, el datapath debe conservar el producto ampliado antes del desplazamiento, sumar el sesgo de redondeo antes de reducirlo y aplicar clamp antes de registrar la salida. Estas son decisiones de implementación coherentes con los modos de cuantización y saturación documentados arriba; no son propiedades de la convergencia real de Newton.
  • Después de cuantizar, la convergencia cuadrática ideal deja de ser una ley exacta: el error puede alcanzar el piso de una ULP y permanecer allí porque la salida ya no tiene más códigos. La garantía de convergencia cuadrática de NIST aplica a la iteración matemática exacta, no automáticamente a una iteración con redondeo y saturación.

Verificación RTL

  • Icarus explica que la simulación compila el modelo y el testbench y luego los ejecuta en un motor de simulación; también señala que el simulador y el sintetizador son herramientas distintas. Esto justifica comprobar funcionalidad y protocolo con el testbench antes de interpretar resultados de síntesis. Icarus Verilog, Simulation Using Icarus Verilog
  • La documentación de Icarus muestra el flujo iverilog -o top.vvp ... seguido de vvp top.vvp; el primero genera el formato ejecutable y el segundo ejecuta la simulación. Icarus Verilog, target VVP
  • Yosys documenta read_verilog para cargar RTL Verilog y recomienda usar un simulador como Icarus para comprobar la sintaxis, porque su frontend no tiene el mismo nivel de diagnóstico. YosysHQ, read_verilog
  • El comando stat de Yosys imprime estadísticas del diseño; por ello sirve para comprobar conteos estructurales como multiplicadores, registros y memorias después de leer/sintetizar el RTL. YosysHQ, stat
