Lección 1 · Ejercicio 3 — Carry Select Adder

Suma binaria y el problema del carry

Para explicar el CSLA primero tenés que poder explicar el problema que resuelve: el sumador más simple (RCA) es lento porque el carry tiene que recorrer los 16 bits de a uno.

Base Ejercicio 1

El objetivo de esta lección

Al terminar vas a poder explicar, con números, por qué un sumador de 16 bits "naive" (el Ripple Carry Adder del ejercicio 1) tarda 32 ns: el carry riplea bit por bit. Ese es exactamente el problema que el Carry Lookahead (ejercicio 2) y el Carry Select (este ejercicio) intentan resolver.

1. Sumar dos bits: sum y carry

Sumar en binario es lo mismo que en decimal, pero la columna solo llega a 1. Cuando dos bits se suman y el resultado no entra en un bit, queda un carry que se arrastra a la columna siguiente:

absumcarry
0000
0110
1010
1101

Ese circuito se llama half adder (sum = a ^ b, carry = a & b) y solo sirve para el bit menos significativo. Para los demás bits falta un dato: el carry que viene de la columna anterior. Ahí aparece el full adder.

2. El full adder (FA), la célula de todo

El full adder suma tres bits: a + b + cin → sum y cout.

  • sum = a ^ b ^ cin
  • cout = (a & b) | (cin & (a ^ b))

En el curso el FA se arma estructural con compuertas primitivas y delays explícitos (ejercicio 1, full_adder.sv):

xor #(TXOR) u_xor_p  (p,   a, b);   // p   = a ^ b        (xor: 2 ns)
and #(TAND) u_and_g  (g,   a, b);   // g   = a & b        (and: 1 ns)
and #(TAND) u_and_pc (pc,  p, cin); // pc  = p & cin
or  #(TOR)  u_or_cout(cout, g, pc); // cout = g | pc       (or:  1 ns)
xor #(TXOR) u_xor_sum(sum,  p, cin);// sum  = p ^ cin      (xor: 2 ns)
  • cin → cout: 2 ns (un and + un or). Es el "salto" del carry dentro de un FA.
  • cin → sum: 2 ns (una sola xor: sum = p ^ cin, y p ya está calculado en paralelo). Aunque la fórmula sea a ^ b ^ cin, el cin no pasa por las dos xors, solo por la última.
  • a → sum: 4 ns (las dos xors en serie: p = a ^ b y luego sum = p ^ cin). Este es el camino de las entradas a/b hasta la suma.

Ese cin → cout = 2 ns es el número que hay que recordar: va a multiplicarse por la cantidad de bits (cada FA agrega 2 ns al camino del carry)

3. El Ripple Carry Adder: encadenar FAs

Para sumar N bits se encadenan N full adders: el cout del FA i es el cin del FA i+1. Eso es el RCA, y se arma con un generate-for. Por ejemplo, analicemos el rca4.sv que usa el CSLA16:

logic [4:0] carry;         //  4 bits + carry de salida
assign carry[0] = cin;     // el carry de entrada del bloque

genvar i;
generate
  for (i = 0; i < 4; i = i + 1) begin : fa_chain
    full_adder u_fa (
      .a   (a[i]),
      .b   (b[i]),
      .cin (carry[i]),
      .sum (sum[i]),
      .cout(carry[i + 1])  // el carry del FA i es el cin del FA i+1
    );
  end
endgenerate
assign cout = carry[4];    // el carry de salida del bloque

El nombre lo dice todo: el carry riplea del bit 0 hast el bit N−1. Cada FA no puede calcular su cout hasta que llega el carry del anterior.

4. El path crítico: el peor caso

El delay de un RCA no es "un promedio" ni una constante: depende de cuánto tenga que viajar el carry. El peor caso es cuando el carry recorre todos los bits.

El ejemplo clásico, y el que usa el testbench:

  0xFFFF
+ 0x0001
  ------
  0x0000  con carry-out = 1

En cada columna se suma 1 + 1: genera carry, y ese carry se suma en la columna siguiente, que vuelve a ser 1 + 1… El carry generado en el bit 0 tiene que atravesar los 16 bits. Ese es el path crítico.

Con el modelo del curso:

  • RCA de 4 bits: el camino del carry cin → cout son 4 × 2 ns = 8 ns. La suma del último bit (sum[3]) sale junto con el carry (8 ns), no después.
  • RCA de 16 bits: 16 × 2 ns = 32 ns.

Conclusion: el delay del RCA crece linealmente con N (O(N)). Doblar los bits duplica el delay. Para 4 bits son 8 ns y para 16 ya son 32 ns.

¿Cuál es el peor caso de un sumador?

0xFFFF + 1. El carry genera en el bit 0 y tiene que recorrer los 16 bits. Por esto existe el CLA y el CSLA.
